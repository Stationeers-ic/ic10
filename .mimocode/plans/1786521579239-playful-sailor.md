# Plan: Split Composite Port Types

## Problem

"Power and Data Input", "Power and Data Output", and "Connection" are composite port types that support both "data" and "power" networks. The current architecture has critical issues:

1. **BiMap loses duplicates**: When `["Connection", "Connection"]` is loaded, BiMap only keeps the last index (index 1), losing index 0. ~150+ devices affected.
2. **Single network per port**: `portNetworks` maps `PortType -> Network`, but composite ports should support multiple networks simultaneously.
3. **Ambiguous type mapping**: `getPortTypes("Connection")` returns `["data", "power"]`, making it impossible to distinguish which network type should be used.

## Solution

Split composite port types into separate entries at the same physical index.

### Changes to `DevicePorts.ts`

#### 1. Change data structures
```typescript
// Before:
private portIndices: BiMap<PortType, number>;

// After:
private portIndices: Map<PortType, number>;
private portIndexToTypes: Map<number, PortType[]>;
```

#### 2. Add helper to expand composite ports
```typescript
private static expandCompositePort(port: PortType): PortType[] {
    switch (port) {
        case "Power and Data Input":
            return ["Data Input", "Power Input"];
        case "Power and Data Output":
            return ["Data Output", "Power Output"];
        case "Connection":
            return ["Data Input", "Power Input"];
        default:
            return [port];
    }
}
```

#### 3. Update constructor to split composite ports
```typescript
this.portIndices = new Map();
this.portIndexToTypes = new Map();
this.scope.rawData?.connections.forEach((connection: PortType, index: number) => {
    const expandedPorts = DevicePorts.expandCompositePort(connection);
    expandedPorts.forEach(port => {
        this.portIndices.set(port, index);
        if (!this.portIndexToTypes.has(index)) {
            this.portIndexToTypes.set(index, []);
        }
        this.portIndexToTypes.get(index)!.push(port);
    });
});
```

#### 4. Update `getPortTypes()` - remove composite cases
Remove the cases for "Power and Data Input", "Power and Data Output", and "Connection".

#### 5. Update `setNetwork()` - use Map instead of BiMap methods
Find compatible port type for the network type at the given index.

#### 6. Update `getNetwork()` - handle multiple types per index
When called with an index, return the first available network. When called without args, return the default (data) port's network.

#### 7. Update all BiMap method calls to Map methods
- `hasValue(port)` → `portIndexToTypes.has(port)`
- `getByValue(port)` → iterate `portIndexToTypes.get(port)` or use reverse lookup
- `hasKey(type)` → `portIndices.has(type)`
- `getByKey(type)` → `portIndices.get(type)`

#### 8. Update fallback in constructor
```typescript
if (this.portIndices.size === 0) {
    this.portIndices.set("Data Input", 0);
    this.portIndexToTypes.set(0, ["Data Input"]);
}
```
