# AGENTS.md - IC10 Emulator

## Project Overview

IC10 emulator and development toolkit for the game Stationeers. TypeScript library built with Bun and Vite.

## Quick Start

```bash
bun install
bun test
```

## Essential Commands

| Command | Purpose |
|---------|---------|
| `bun test` | Run all tests |
| `bun run fix` | Fix lint + format issues (Biome) |
| `bun run format` | Format code only |
| `bun run lint` | Check lint only |
| `bun run dev` | Development mode with file watching |
| `bun run upgrade` | Full rebuild: download data → generate → test |
| `bun run build` | Production build (generates → tests → vite → tsc) |

## Core Patterns & Principles

### 1. Dual-Pass Execution (Sandbox + Real)

The emulator runs IC10 code in **two passes**:

1. **Sandbox pass** — validates syntax, parses labels/aliases/defines, checks argument counts. No real devices needed.
2. **Real pass** — executes with actual device state, register operations, jumps.

```typescript
await runner.run();                    // sandbox pass
runner.switchContext("real");
await runner.run();                    // real pass
```

Both contexts share the same `ContextSwitcher`. The default is "sandbox".

### 2. Core Class Hierarchy

```
Device (abstract)
  ├── Structure (abstract) — game structures
  ├── Item (abstract) — player items
  ├── Entity (abstract) — dynamic entities
  └── Housing (extends Device) — chip socket
       ├── StructureCircuitHousing (auto-generated)
       └── SandBoxHousing
```

**Chip** — programmable IC10 chip with 18 registers (r0-r17), Stack memory (512 entries), and defines map (aliases, constants, labels).

**Housing** — chip socket that connects up to 6 devices via pins. Pin -1 = housing itself ("db" register).

**Network** — data/power/pipe network. Devices share networks and communicate via ports.

### 3. Device Subsystems

Each `Device` instantiates subsystems based on tags from `DEVICES` data:

| Subsystem | Purpose | Created When |
|-----------|---------|--------------|
| `$ports` | Network port management | Always |
| `$props` | Logical properties (read/write) | `HasLogic` tag |
| `$reagents` | Chemical reagent storage | `HasReagent` tag |
| `$memory` | Device-level memory (Stack) | `HasMemory` tag |
| `$slots` | Equipment slot management | `HasSlot` tag |
| `$errors` | Per-device error collection | Always |

`DeviceProps` uses `BiMap<string, number>` for property mapping and enforces read/write permissions from device data.

### 4. Instruction System

Every IC10 instruction extends abstract `Instruction` class:

1. **`argumentList()`** — returns array of `InstructionArgument` descriptors with:
   - `name` — for named access
   - `canBeAlias/const/define/label` — substitution permissions
   - `calculate(context, argument)` — parsing function

2. **`run()`** — instruction logic using `getArgumentValue<T>()` for resolved values

3. **`execute()`** — validates argument count, calls `run()`

4. **`static tests()`** — returns `InstructionTestData[]` for auto-discovery

**Argument Resolution** (`getArgumentValue`):
- Checks defines/aliases/labels/consts
- Substitutes based on argument permissions
- Calls `calculate()` for final parsing (number, register, device pin, logic enum)

**Argument Calculators** (`ArgumentCalculators`):
- `anyNumber()` — decimal, `$hex`, `%binary`, `HASH()`, `STR()`, constants
- `registerLink()` — `rN` (direct), `rrN` (recursive/pointer chain)
- `devicePin()` / `deviceId()` — `dN`, `db`, `dN:port`, `drN`, `drrN`
- `logic()` / `logicSlot()` — enum values by name or code
- `jumpTarget()` — number or label

**Instruction Categories**:
- **Math** — `add`, `sub`, `mul`, `div`, `abs`, `sqrt`, `sin`, `cos`, `and`, `or`, `xor` (uses exact-ic10-math for game-accurate precision)
- **Jump** — `j`, `jal` (writes RA), `jr` (relative), conditional `je/jne/jgt/jlt/jge/jle`
- **Condition** — `seq/sne/sgt/slt` (set 1/0), `beq/bne/bgt/...` (branch), `bal/...` (branch-and-link), `sel` (ternary)
- **Device** — `s/l` (set/load property), `get/put` (device memory), `lb/sb` (batch by hash), `ls/ss` (slots), `lr` (reagents)
- **Misc** — `alias`, `define`, `move`, `push/pop/peek/poke`, `sleep`, `yield`, `hcf`

### 5. Lines System

- **InstructionLine** — looks up instruction from `instructions` map, creates instance, calls `execute()`
- **LabelLine** — registers position as define during `init()` (processed before execution)
- **CommentLine** / **EmptyLine** — no-ops, advance PC

Jump instructions return `true` from `end()` to prevent double PC advancement.

### 6. Self-Contained Tests

Each instruction class defines its own `static tests()` method:

```typescript
static tests(): InstructionTestData[] {
    return [
        {
            title: "Add two numbers",
            code: ["add r0 1 2"],
            expected: [{ type: "register", register: 0, value: 3 }]
        }
    ];
}
```

Test runner auto-discovers all instruction tests. Tests run in dual context (sandbox + real).

**Test Data Structure**:
- `code` — IC10 source (string or array)
- `devices` — test devices to connect (pin, id, device instance)
- `expected` — register values, device properties, stack values, next line index
- `iterations_count` — for step-by-step execution

### 7. Code Generation (tools/)

| Script | Produces |
|--------|----------|
| `generate-devices.ts` | Device classes using Babel AST |
| `generate-index.ts` | `src/index.ts` barrel exports |
| `generate-intruction-index.ts` | `instructions` map in `src/Ic10/Instruction/index.ts` |
| `generate-schema.ts` | `env.schema.json` from valibot |
| `generate-vscode.ts` | VS Code language config |
| `generate-langs.ts` | i18n language files |
| `download.ts` | Fetches game data from API → `src/Defines/` |

Device generation uses **Babel AST** (not string templates) to ensure syntactically correct output.

### 8. Event-Driven Architecture

Both `Ic10Runner` and `Context` extend `EventEmitter` with granular events:
- `run`, `step`, `stepEnd`, `contextSwitch`
- `error`, `fatalError`, `stop`
- Register read/write, stack push/pop, device parameter read/write

Enables external tools (IDEs, debuggers) to observe execution without modifying the emulator.

### 9. Error Severity Levels

| Level | Behavior |
|-------|----------|
| Weak | Info only |
| Warning | Accumulated for reporting |
| Strong | Program-breaking |
| Critical | Halts execution immediately |

### 10. Deterministic Randomness

Per-runner and per-line random seeds ensure reproducible results across sandbox and real passes.

### 11. Context Inheritance Chain

RealContext uses 10+ level inheritance:
```
Context → ExecutionBase → DefinesBase → MemoryBase → DeviceHelpers
→ DevicesByPinBase → StackBase → DevicesByHashBase → DevicesByHashAndNameBase
→ DevicesByIdBase → DevicesSlotBase → DevicesReagentBase → RealContext
```

Each layer adds one interface implementation (interface segregation).

### 12. Entry Points

- **`Ic10Runner`** — main class for running IC10 code
- **`ValidateIc10Runner`** — static utility for quick syntax validation
- **`Chip`** — programmable chip with registers and memory
- **`Housing`** — chip socket connecting devices
- **`Network`** — device network

## Gotchas

- `bun run build` requires full generation cycle — use `bun run build` not `vite build` alone
- `src/index.ts` is auto-generated — manual edits get overwritten
- `bun run upgrade` downloads data from external API — may fail if network is unavailable
- Instruction `end()` returning `true` prevents double PC advancement
- Pin -1 in Housing = housing itself (accessed as "db" register)
- `rrN` / `drrN` follow pointer chains (recursive dereferencing)
- Sandbox returns 0 for all device operations; Real uses actual state
